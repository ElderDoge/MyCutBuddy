# 剪辑全过程与配置指南

本文按实际操作顺序说明从素材到剪映草稿的完整过程，并给出每个配置项的业务含义与填写建议。命令与字段合同见 [本地 CLI](cli.md)，计费口径见 [积分](billing.md)，网盘与本地安装见 [网盘与草稿](baidu-drive-and-drafts.md)，成套做法见 [场景示例](examples.md)。

```text
项目 → 素材库（上传分享 → 导入 → 整理 → 索引）→ 风格/样式预设
     → 填写配置 → 估算或确认费用 → 提交 → 跟踪任务 → 下载草稿包 → 安装剪映
```

## 1. 先选剪辑形式

| 形式 | 输入 | 前置条件 | 主要费用来源 |
|---|---|---|---|
| 旁白 `narration` | 文案（AI 配音）或语音配音库文件二选一 | 主素材库索引就绪 | 文案字数或配音时长、候选素材数、是否开特效 |
| 片段口播 `segment_composition` | 完整文案或剪辑指令二选一 | 人物口播库有启用且已索引的候选 | 估算时长、口播候选数、是否叠加主库画面、是否开特效 |
| 完整口播 `full_video` | 口播源视频 + 可选参考文案 | 所选源视频已上传，不需要索引 | 源视频时长、主素材候选数、是否叠加画面、是否开特效 |

判断原则：只有旁白配音，画面中不需要出现人物出镜口播，选旁白；需要使用真人出镜的多段素材进行口播剪辑，选片段口播；已经有一条完整口播视频，只需要切片和字幕，选完整口播。完整口播比片段口播少一个口播选段剪辑阶段，费用更低，但不会改变选中口播视频内的讲话内容。

## 2. 项目与素材库

### 2.1 建项目和选库

一个项目是一套素材库加它自己的剪辑任务。素材围绕同一产品或同一批内容时放同一个项目；素材完全不同时新建项目。

| 库 | `library_type` | 放什么 | 上限 |
|---|---|---|---|
| 主素材库 | `primary` | 旁白和口播用的 B-roll 视频、图片；可写目录描述 | 2,000 |
| 人物口播库 | `talking_head` | 出镜视频（必须有可读音轨）和口播音频 | 1,000 |
| 语音配音库 | `voiceover` | 只放配音音频 | 1,000 |

`material.directory`、`material.manage` 和导入失败提示命令显式传 `--library`；导入和索引在 `--input` 里带 `library_type`。格式清单与跳过规则见 [本地 CLI](cli.md) 的素材库部分。

### 2.2 上传与分享

用官方 `baidu-drive` Skill 上传并生成分享链接、提取码，再把链接交给剪搭子导入。**建议把素材整理放在上传之前**：导入后要整理也可以，但整理能力较少，通常只能整个文件夹移动或改名。

- 一个项目或一次导入建一个独立目录，不要把多个项目混在一起。
- **主素材库一个视频文件只能放一个镜头**：当前只支持单镜头素材，一个文件内含多个镜头（成片、宣传片、多场景录屏等）不会被自动识别和切分，必须先在导入主素材库前切成一镜一个文件。主素材库的多镜头素材上传与自动切分是后续能力，不要把切分工作交给剪搭子，也不要向用户承诺自动拆分。人物口播库不要求预先切分，多段出镜素材可以放在同一文件里，由片段口播自行选段。
- 分享里只放会用的素材。重复文件虽然不会重复入库，但仍计入下载体积，直接删掉更省积分。
- 超过 10 Mbps 的视频会明显增加上传、下载压力，并提高导入所需积分。有条件时先由 Agent 压缩素材库再上传：
  - H.264：`crf 20–23`。
  - 超过 2.5K 分辨率：先缩到 2.5K，可用稍高的 `crf 23`。
  - 电脑性能不错：可改用 HEVC，`crf 24–27`。
- 完全不分类也能正常剪辑，但不同素材放进不同目录能显著提升剪辑效果、方便管理。建议至少按内容或用途分到不同目录。
- 目录层级不要太深：导入根目录以下，文件父目录最多 6 级。
- 人物口播库只放含可读音轨的视频和音频；语音配音库只放音频。放错库会在导入时被跳过或整次失败。
- 分享链接必须是 `pan.baidu.com` 的 `/s/` 或 `/e/` 链接，链接自带提取码时以链接为准。
- 剪搭子不生成素材，也不能从互联网下载素材。如有这些需求，先用其他方法得到素材，再上传即可使用。

网盘官方skill上传和下载都不稳定容易断开，下载尤其受会员状态影响：

- 上传速度无论是否 SVIP 都基本不限速，在 20 Mbps 以上。
- 下载速度在非 SVIP 下限速比较严重，在 1 Mbps 以下。
- 预计上传或下载超过 10 分钟时，建议用户手动上传或下载，避免浪费时间；10 分钟以内由 Agent 直接代替用户执行，这样更方便。

不需要手动整理废片，也不需要自行修剪每个镜头开头结尾不能用的地方，这些剪搭子都会处理。服务端下载素材需要一定时间，如果需要转码则需要更多时间，需要耐心等待；如确需计算处理时间，在服务器空闲不排队时，可按 300–500 Mbps 下行、耗时约为素材时长的 1.5 倍估算。

### 2.3 导入并等待终态

```bash
node scripts/mycutbuddy.mjs material.import.submit --project <项目 ID> --confirm-charge \
  --input '{"library_type":"primary","share_url":"https://pan.baidu.com/s/...","extraction_code":"..."}'
```

- 导入是合并添加，不是整库替换。服务端先扫描、下载、去重和准备，准备完成后自动按实际结果扣费。
- `prepared`、上传成功或受理回执都不代表素材已入库。用 `request.watch` 跟到请求终态，再读 `material.directory` 确认素材数量和结果行。
- 导入不会自动索引；主库和口播库还需要整理后单独索引。
- 同一个库同一时间只能有一个素材工作；不同库可以并行。任何一个库有活动素材工作时，项目不能提交新的实际剪辑。

### 2.4 整理素材

导入完成后先整理，再索引。整理本身不扣积分，但保存后会让相关索引过期，所以尽量一次改完。

**整理和目录描述都是可选项，不整理也能正常剪辑。** 但建议至少填写根目录描述，帮助 AI 理解拍摄内容；目录分得越清楚，画面匹配越准确。

- **目录**：按产品、场景、人物、卖点或拍摄批次分组；根目录为 `.`。目录操作和素材属性都通过 `material.manage` 一次性提交，按数组顺序解释。
- **目录描述**（仅主库）：这是给素材补充文字说明的唯一方式。根目录写清楚是什么产品、有哪些部件、状态或使用场景；子目录只在明显不同于其他素材时写，例如「竞品」「网络素材」。最多 1,000 字。描述留空也能索引，但匹配会差一些。真实项目的写法和完整示例见 [场景示例](examples.md) 第 3 节。
- **文件名**：逐条改，用于后续识别和匹配；不要只靠文件名描述画面。
- **启用**：真正会参与剪辑的才启用。禁用的素材不参与匹配，也不计入下一次索引费用。
- **使用次数 / 不限使用次数**：影响「素材使用次数阈值」和「高频素材排除比例」。不限使用次数不是给常用主镜头设置的；一般只在特殊情况设定：剪辑逻辑或要求中必须要有这些镜头存在，同时这类素材又比较少时，才设为不限，避免它们达到阈值后被排除。
- **启用同期声**：索引会根据声音是否有意义、是否没有杂音自动判断，一般不用手改。保留同期声的素材会按「素材同期声量倍率」出声，其余静音，避免和旁白打架。
- **可用开始 / 可用结束**（秒）：索引也会自动判断每个素材可用的开始和结束位置，一般不用手改；只有需要强制只使用某一段时才手动填写，例如人物只保留出镜部分、去掉开头空镜。

主库可改全部属性；人物口播库只能改文件名和启用；语音配音库的素材只能移动和删除。人物口播库建议保持精简，确定不再使用的内容建议删除，否则会影响剪辑质量与积分消耗。

### 2.5 索引

只有主素材库和人物口播库需要索引，语音配音库不需要。索引建立后，素材才能参与画面匹配或片段选段。

```bash
node scripts/mycutbuddy.mjs material.index.submit --project <项目 ID> --confirm-charge \
  --input '{"library_type":"primary"}'
```

- 先保存素材管理，再索引；有未保存修改时不能索引。
- 索引速度较快：不排队时，100 个素材通常数分钟内完成。
- 只对启用且待索引、或索引已过期的素材计费。把确定不用的素材先禁用，再索引，可以少花钱。
- 索引完成后状态为就绪；之后任何目录、描述或属性改动都会让相关索引过期，需要重新索引。
- 旁白和片段口播要求对应库索引就绪；完整口播不要求索引，但叠加主素材库画面时要求主库索引就绪。

## 3. 风格与样式预设

三类风格目录互相独立，只能在同一形式的目录里选择：`narration`、`talking_head_segment`、`talking_head_full`。

如果用户没有特殊要求，推荐使用系统默认风格，比较均衡。只有用户明确提出节奏、画面或特效偏好时，才调整为个人风格或修改字段。

1. `editing.context --project <项目 ID>` 读取公开字段元数据、资源目录、三类风格列表、当前余额和计费提示版本。
2. `preset.style.list --project <项目 ID> --form <形式>` 选风格；`preset.style.get` 取得该风格的完整 `public_config`（口播风格还会带 `use_primary_overlay`）。
3. 以这份配置为底，只改用户要求的字段。系统风格只读；需要保存改动时用 `preset.style.create` 另存个人风格，或对个人风格用 `preset.style.update`。
4. 旁白风格只记录「配音来源」这一项选择，不保存具体的配音文件、文件名或参考文案；口播风格记录叠加主库画面的默认值。临时任务的修改不会自动写回预设。

保存个人风格时还要填：

| 字段 | 怎么填 |
|---|---|
| `name` | 能一眼分辨的名称，建议「产品/题材 + 形式 + 节奏」，例如「短袖-信息流-快节奏」。 |
| `description` | 适用场景、节奏和特殊要求，最多 500 字；用于搜索和后续选择。 |
| `tags` | 逗号分隔的关键词，最多 20 个，例如「服饰,信息流,快节奏」。 |
| `style_category` | 必须与当前形式一致：`narration`、`talking_head_segment` 或 `talking_head_full`。 |
| `narration_audio_source` | 仅旁白风格可填 `tts` 或 `upload`，表示默认配音来源。 |
| `use_primary_overlay` | 仅口播风格可填，表示默认是否叠加主素材库画面。 |

字幕与固定文字样式必须来自用户在剪映里已经做好的完整样式草稿，经网盘上传分享后导入提取，不能由截图或文字描述生成。草稿怎么做、多个文字层怎么分组、固定文字为什么要放在不同时间点，见 [自定义资源预设](custom-presets.md)；上传与导入命令见 [网盘与草稿](baidu-drive-and-drafts.md)。

## 4. 配置怎么填

### 4.1 通用原则

- `public_config` 必须是完整配置快照，以所选风格的 `public_config` 为底，不要只提交几个覆盖项。
- 下表写的「默认」是字段合同默认值；实际起点是所选风格的值，可能不同，例如系统信息流风格会开启调色和特效。
- 字段名、范围、步长、默认值和显示条件以 `editing.context` 的元数据为准；资源类字段必须使用当前资源目录里的真实 ID，不能填显示名称或路径。
- 「主开关关闭」时，从属字段不生效；重新打开后原值仍在。不要给关闭的功能强行塞资源。
- 人物口播的 `public_config` 不能包含任何 `tts_` 开头的字段。
- 批量时，普通字段留空继承统一值，填写后覆盖本行；七项提示词字段是追加在统一值之后。

### 4.2 任务层输入

| 字段 | 怎么填 |
|---|---|
| `audio_source` | 旁白专用。`tts` 用文案生成配音；`upload` 引用语音配音库已发布 MP3。口播不要带这个字段。 |
| `script_text` | 旁白 TTS 的必填文案，最多 3,000 个有效字符；选择配音文件时因文案会自动识别，这里填写的只作字幕校正，无需和配音文件完全一致。也可以只填写校正参考内容，例如高频词汇，也可留空。批量时只能放在 `rows` 里。 |
| `draft_name` | 可选，最多 40 个安全字符；留空由系统生成。批量内不能重名。在剪映中导出视频成片时，也会作为默认文件名。 |
| `preset_source` | 正式提交用 `{kind:"system"|"personal", preset_id}`；口播估算阶段改用 `preset_id`。 |
| `rows` | 批量 1 至 200 行；旁白每行可带 `script_text`、`draft_name`、`audio_source`、`audio_file_relative_path`、`public_overrides`。 |

上传配音的路径填写规则：填语音配音库里的**显示路径**，并省略最后一个 `.mp3`。真实文件 `配音/1.wav.mp3` 填写为 `配音/1.wav`；不能填用户电脑上的本地路径。

### 4.3 文案与配音

`tts_`开头的字段只对TTS作用，此外的字段对所有形式都有作用。

| 字段 | 作用 | 怎么填 |
|---|---|---|
| `tts_voice_name` / `tts_voice_preset_id` | 具体音色或音色预设，二选一 | 要指定声音选具体音色；无需指定且希望有变化时选预设，预设是一组预定义好的音色，每剪辑一条都会根据权重随机抽取。 |
| `tts_speed` | 配音合成语速，0.5–2.0 | 一般保持1.0或默认。建议速度主要由`voice_speed_ratio`叠加控制。两者会叠加。 |
| `voice_speed_ratio` | 成片人声播放速度，0.5–2.0。 | 常规短视频节奏建议保持 1.1-1.2，1.0较慢，1.3较快。 |
| `speech_pause_target_ms` | 剪气口，超过该时长的停顿压到该值，0–2000，0表示不剪气口。 | 默认 250；快节奏用 100–200，情感或教程用 300–500。 |
| `tts_volume` | 配音合成音量，0.5–2.0 | 一般保持 1.3 不变。 |
| `tts_pronunciation_optimization_prompt` | 专门纠正读法，优化TTS读音 | 写易读错的品牌名、缩写、数字、易读错的词，例如「SKU 读 S-K-U，数字写成汉字」。 |
| `voice_track_volume` | 成片人声主轨音量，0–3 | TTS建议 2.0-2.4，配音文件或口播可先默认2.0，根据反馈调整 |
| `clean_material_audio_volume` | 保留同期声素材的音量，0–3 | 建议默认0.5；根据反馈调整。如果视频类型同期声比较重要，可以写1.0或更高。如果明确不需要同期声，可以0 |

用「配音文件」时，所有 `tts_` 合成设置不参与；「成片人声播放速度」和「剪气口」仍然生效。

### 4.4 画面素材选择

此处只对主素材库作用。在旁白形式中，控制画面的选择。在口播形式中，控制叠加画面（B-Roll）的选择。

| 字段 | 作用 | 怎么填 |
|---|---|---|
| `material_matching_requirements` | 选画面的文字要求 | 根据实际需求填写，留空保持默认均衡规则 |
| `candidate_keep_ratio_percent` | 每次从全部候选中随机抽取多大比例参与剪辑，用来控制剪辑效率和降低大量剪辑时的重复性，10–100。 | 素材很多或想控制费用时降到 30–60；素材很少或要求高时保持 80–100。逻辑：在确保素材足够完成本视频剪辑的基础上，越低就越能控制重复性和降低成本 |
| `max_usage_count` | 素材使用次数阈值，0–500。未达阈值时不会排除，达到阈值后可能排除。 | 默认 5；根据用户要求和预计制作规模决定。同一镜头反复出现时降低阈值。 |
| `top_usage_exclude_percent` | 按比例排除高频素材，除非阈值未达设定值。0–100 | 默认 10；想更强去重时提高，建议最高不超过50%，否则可能没有足够的合适画面可用。0 表示达到阈值就全部排除。 |
| `enable_folder_candidate_ratio_control` | 按目录分别控制素材参与比例。 | 默认关闭。只有确实要按目录取舍素材时才打开；打开并填写至少一项后，未配置的目录会被全部排除；配置留空时整个目录筛选不生效。 |
| `folder_candidate_keep_ratios` | 各目录的保留比例，与总比例叠加作用。 | 按 `相对目录:比例` 填写，格式和示例见下方说明。 |
| `visual_segmentation_prompt` | 画面切换节奏 | 留空为默认节奏，可填入较快或较慢，也可以用时间或字数来精确描述，例如「开头 3 秒每 5–8 个字切换；产品特写停 X 秒」。 |
| `enable_main_talking_head_visual_analysis` | 口播逐段分析主视频画面 | 默认开启；只有口播使用，旁白没有这一项。 |

`folder_candidate_keep_ratios` 的填写规则：

- 只有 `enable_folder_candidate_ratio_control=true` 时才生效；关闭时整段忽略。
- 格式为 `相对目录:比例`，多组用英文逗号分隔，例如 `产品:100,竞品:50`。必须使用英文冒号 `:` 和英文逗号 `,`；比例是 0–100 的百分数，最多 1,000 字符。
- 目录是素材库内的相对路径，用 `/` 分隔，不写开头的 `/`，也不能写本机绝对路径。例如 `产品`、`产品/细节`、`竞品`。
- 按路径前缀匹配：写 `产品` 会覆盖 `产品` 下的所有层级；同时命中多个配置时，路径更长的优先。例如同时写 `产品:100` 和 `产品/口播:0`，则 `产品/口播` 下的素材全部排除，其余 `产品/...` 保留。
- 开关打开且至少配置一项后，没有命中任何配置的素材按 0% 排除，包括直接放在素材库根目录的素材。想让根目录素材参与，先把它们移进已配置的子目录。开关打开但配置为空时，目录筛选不生效，全部候选仍按总比例参与。
- 比例大于 0 时，该目录至少保留 1 个素材；比例为 0 时全部排除。
- 这个比例叠加在「候选素材保留比例」之后：先从全库按总比例随机抽取，再在每个命中的目录内按目录比例随机抽取。实际保留量接近两者相乘，例如总比例 50% 加目录比例 80%，大致保留 40%。

示例：`产品:100,产品/口播:0,竞品:50`

- `产品` 及其子目录（除 `产品/口播`）全部参与。
- `产品/口播` 不参与。
- `竞品` 保留 50%。
- 其他目录以及直接放在库根目录的素材不参与。

| `clean_material_audio_volume` | 见「文案与配音」表，控制同期声。 |

### 4.8 语音字幕

| 字段 | 怎么填 |
|---|---|
| `dialogue_subtitle_style` | 从资源目录选语音字幕样式；用户有品牌样式时优先用个人样式。 |
| `enable_subtitle_markup_optimization` | 开启后，可以会对重点字做重点标注、并删除因为添加了花字而变得没必要的语音字幕。 |
| `subtitle_markup_user_prompt` | 默认留空。如有需求，可指定重点标注内容、频次、是否删除字幕，例如「只标产品卖点，其他不标；不隐藏任何字幕」。 |
| `subtitle_segmentation_user_prompt` | 语音字幕的分行要求，默认留空。填写可改变逻辑，例如「卖点列举每个卖点单独一行」。 |
| `subtitle_segmentation_max_width` | 每行最大汉字宽度，5–50，默认 10，单位“汉字宽度”；竖屏根据文字大小，通常 8–12。这几乎是硬限制，通常用来保证字幕不会出现两行。 |

### 4.10 提示词写法

提示词是给剪辑系统的业务要求，不是脚本或字幕。写法要具体到「什么内容、什么位置、做什么、不做什么」，以下是常见用法：

- 素材匹配：`第一个镜头选择人物和产品共同出镜的；竞品相关段落只用“竞品”目录。`
- 画面分段：`开头 3 秒每 4–8 个字切一次；其余按照较慢节奏。`
- 特效策略：`列出卖点时加列举型花字；竞品缺点用负面音效；转场只在场景切换处使用；不添加复杂特效。`
- 发音优化：`IN77读“印七七”；SKU 读 S-K-U；19.9 读十九块九。`
- 字幕标注：`只标注产品名、价格和行动引导，其他文字不标；不要删除任何字幕。`
- 字幕分段：`不要在 abcd EFG 之间断行。`
- 文字替换：`“最”改成“Z”，“第一”改成“TOP1”，其他绝对化用语按同样方式规避。每一句结尾可添加一个emoji`

**注意**：

1. 无特殊要求时，所有提示词都建议留空。默认逻辑会很好的处理多数常见情况，写提示词反而影响默认处理逻辑。只有在明确指定风格时才需要填写，并且只填写必须明确的内容。
2. 批量剪辑时，每行提示词字段并不会覆盖单条提示词，而是会拼接。

最多 2,000 字；批量逐行填写时追加在统一提示之后，合并后不能超过 4,001 字。不要写与技术字段无关的闲聊。

## 5. 人物口播的两条路径

### 5.1 片段口播

每行至少填 `script` 或 `instruction` 之一：

- `script`：用于在人物口播库的候选片段中选段，并生成字幕。
- `instruction`：说明选段和剪辑要求，不生成配音；没有文案时，要写清成片时长、主题和结尾动作引导。

有文案时按时长 `ceil(有效字数 / 5)` 估算，最少 1 秒；只填指令时按 30 秒估算。候选范围固定为口播库中全部启用、已发布、有可读音轨、已索引且未过期的视频和音频，不能自己挑一个候选子集。成片时间轴必须在 0–600 秒之间，超过会失败。

先估算，再提交：

```bash
node scripts/mycutbuddy.mjs editing.estimate --project <项目 ID> --input-file /tmp/segment-estimate.json
node scripts/mycutbuddy.mjs editing.submit --project <项目 ID> --confirm-charge --input-file /tmp/segment-submit.json
```

估算输入用 `talking_head_path`、`preset_id`、`use_primary_overlay`、`public_config`、`rows`；正式提交把 `preset_id` 换成 `preset_source`，并原样带上返回的 `estimate_token`。改动文案、行、视频、风格或覆盖后必须重新估算。

叠加主素材库画面：开启时按文案从主库挑画面，要求主库索引就绪；关闭后只显示口播画面，也不再要求主库索引。音频片段本身是黑底，关闭覆盖时黑底会保留。

### 5.2 完整口播

每行必须有一个 `main_video_material`，从 `editing.context` 的口播可选视频里精确选择：

```json
{"material_library_id":"<口播库 ID>","material_id":"<素材 ID>","relative_path":"<库内相对路径>"}
```

- `instruction` 必须为空字符串；`script` 可空，只用于校正字幕，例如填「剪搭子、SKU、19.9 元」。
- 源视频时长必须在 0–600 秒之间；不接受音频作为源视频。
- 不需要口播库索引；叠加主素材库画面时仍要求主库索引就绪。
- 费用只与源视频时长、主素材候选数和两个开关有关，参考文案不影响金额。

## 6. 批量提交

- 行数 1–200。批量没有折扣，按行单独计价后求和。
- `rows` 内每行必须有唯一 `row_id`（口播）或按顺序提交；`draft_name` 在同一批次内不能重复。
- 普通字段留空继承统一配置；七项提示词字段追加；`script_text`、`draft_name`、`audio_file_relative_path`、`main_video_material` 等行专属字段不继承。
- 任一行不合法时整批失败，不扣积分、不创建任务；不会只执行合法行。
- 旁白批量在预检通过后按整批一次扣费；口播按各自路径的阶段结算。

## 7. 提交、跟踪与取消

```bash
node scripts/mycutbuddy.mjs request.watch --project <项目 ID> --request <请求 ID>
node scripts/mycutbuddy.mjs task.watch --project <项目 ID> --task <执行任务 ID>
```

- 请求状态：`quoting`、`ready`、`submitted`、`failed`、`cancelled`。`submitted` 只表示执行任务已创建，不是剪辑完成。
- 任务状态：`preparing`、`test_running`、`formal_running`、`test_uploading`、`formal_uploading` 为进行中；`completed`、`partial_completed`、`test_succeeded`、`failed`、`test_failed`、`cancelled` 为终态。`test_succeeded` 是测试结果，不是正式草稿；`local_demo` 装在执行节点，不在用户电脑。
- 取消边界与退款口径见[积分](billing.md)第 4 节；退款一律以服务端账本为准，不自行承诺全退。
- 停止查询不等于取消；受理取消不等于清理完成。取消后要跟到终态。

## 8. 交付到剪映

任务进入 `completed` 后，从 `task.get`/`task.list` 读取 `artifact` 的真实包名、成功成员和过期时间，用项目分享入口与提取码交给 `baidu-drive` Skill 下载。项目分享里可能有其他任务的包，只取本任务需要的包。

下载后：

1. `delivery.inspect` 预检压缩包。
2. `delivery.extract` 解压到新目录。
3. `delivery.install` 安装到剪映草稿目录。通常直接用默认路径：
   - Windows：`%LOCALAPPDATA%\JianyingPro\User Data\Projects\com.lveditor.draft`（即 `C:\Users\<用户名>\AppData\Local\JianyingPro\User Data\Projects\com.lveditor.draft`）。
   - macOS：`~/Movies/JianyingPro/User Data/Projects/com.lveditor.draft`。
   - 只有用户改过「全局设置 → 草稿位置」时，才使用用户提供的实际路径。
4. 安装前先关闭剪映。安装完成后告诉用户：打开剪映，在首页按**今天的日期**（例如 `2026-10-20`）查找本批草稿。
5. 若草稿打开异常（有时与安装时剪映正开着有关），关闭剪映后重新安装草稿，再重新打开剪映；若同名草稿阻止安装，先删除这次刚安装的异常草稿目录再重装。
6. 建议用户在剪映全局设置中关闭草稿自动备份：它会在后台持续打开新草稿，而新草稿首次打开又很慢，会导致剪映卡到不能动弹。

三步分别报告。同名草稿不覆盖；不改写草稿 JSON 或 UUID。纯云端环境无法写入用户电脑时，提供真实下载信息与手动安装步骤。
