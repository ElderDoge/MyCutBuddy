# 场景示例：按需求选择剪辑做法

本文只讲不同剪辑需求怎么落地：选哪种形式、素材库怎么分、目录描述写什么、不同形式的差异调哪里。字段含义和完整配置见 [剪辑指南](editing-guide.md)，命令与参数见 [本地 CLI](cli.md)。

示例中的 ID、路径、样式和配置快照都要替换成 CLI 当前返回的内容。`public_config` 始终放所选风格的完整快照，不要只提交下面提到的差异字段。

## 1. 先判断形式

画面中不需要人物出镜，用旁白 `narration`；出镜素材是多段短片，用片段口播 `segment_composition`；已经有一条完整口播视频，用完整口播 `full_video`。口播再决定是否用 `use_primary_overlay` 叠加主库画面。三种形式的输入、前置条件和费用见 [剪辑指南](editing-guide.md) 第 1 节。

## 2. 素材库怎么整理

一个素材库只选一个主分类轴。

| 主分类轴 | 适合 | 目录示例 | 说明 |
|---|---|---|---|
| 产品 / 品类 / 主题 | 多产品、多 SKU、持续来料 | `产品名/`、`产品名/子主题/MMDD/` | 父目录写清产品边界，子目录再分主题或批次 |
| 拍摄批次 | 单一产品或主题、按天拍摄 | `MMDD/` | 只在批次内容确实不同时使用 |
| 画面类型 / 来源 / 用途 | 图片、视频、开场、证据、网络素材混用 | `图片/`、`开头视频/`、`获奖素材/`、`网络素材/` | 便于按目录限制参与比例 |
| 不分类，整库平铺 | 单一主体、素材量不大、场景靠描述区分 | `V00001.mov`、`V00002.mov` | 根目录描述承担全部分类信息 |
| 人物 / 批次（口播库） | 多段出镜素材 | `人物名/`、`MMDD/` | 只保留确定会用的片段，口播库不能写目录描述 |
| 配音批次 / 说话人（配音库） | 已有配音文件 | `批次名/`、`说话人/` | 只放音频，不需要索引 |

**主素材库每个视频文件只放一个镜头。** 主素材库当前只支持单镜头素材：成片、宣传片、多场景录屏必须先切成一镜一个文件再导入，平台不会自动识别和切分；主素材库的多镜头素材上传与自动切分是后续能力，现在不要按它规划。人物口播库不受此限，多段出镜素材可以放在同一个文件里。切分镜头不等于剪掉每个镜头内的废片头尾，那部分仍由剪搭子处理。

## 3. 目录描述怎么写

目录描述就是主素材库的 `material_description`。

- 只有主素材库可以写；人物口播库和语音配音库没有这个能力。
- 描述按目录逐级继承：根目录写全库共同事实，子目录只写该目录独有的差异。
- 单条最多 1,000 字。留空也能索引，但匹配会差。
- 改动目录或描述会让相关索引过期；一次改完，再索引。

描述写四类事实：

- 对象边界：是什么产品、什么型号，画面里固定出现什么。
- 可见部件与状态：外观、材质、包装、颜色、结构、特殊效果。
- 常见动作与场景：谁在做什么、在什么环境、什么拍摄方式。
- 画面无法支撑的信息不要写：价格、销量、参数、功效、认证等。

模板：

```text
本素材库是【对象】的【素材类型】。主体是【外观、包装、部件、型号】；
常见画面有【动作、场景、拍摄方式】。
```

不要把“只写可见内容”“不要补充画面外信息”这类指令写进描述。分析器默认按画面理解，描述本身把事实写清楚就够了；这类句子不会提高准确率，还占字数。

### 3.1 示例

**多产品：根目录写范围，子目录写具体产品**

根目录：

```text
本素材库包含多款同品类产品，目录名称表示具体产品。
画面类型包括外包装、内包装、产品本体、配件和使用场景。
```

子目录：

```text
本目录是套组素材，画面可能同时出现套组内的多款产品。
```

**来源和证据混用：根目录固定对象，子目录写来源**

根目录：

```text
本素材库是某产品的官方宣传素材：产品外观、内部结构或使用场景、
官方卖点片切分出的镜头、人物出镜、奖项证书图片和网络图片。
```

`网络图片/`：

```text
用于开场吐槽的流行表情包，不是产品素材。
```

`获奖素材/`：

```text
奖项证书、奖杯和相关测试视频，画面文字是奖项信息。
```

`官方资料/`：

```text
官方宣传片切分出的镜头，可能包含带字幕版、有旁白版和无字幕纯净版。
画面里的产品固定是同一款。
```

**录屏：写清画面主体，不把固定界面当内容**

`成品录屏/`：

```text
本目录是成品展示，画面主体是预览窗口里正在播放的成片；
剪辑软件的时间线、按钮和菜单是固定界面，不属于画面内容。
```

`操作录屏/`：

```text
本目录是操作演示，画面重点是鼠标指针、正在输入的内容和附近区域；
其他未操作区域是固定界面。
```

### 3.2 常见错误

**目录描述**

| 写法 | 问题 |
|---|---|
| “这里都是好素材，随便用” | 没有提供任何可匹配的画面事实 |
| “产品很好用，性价比高，销量第一” | 画面看不出来，属于文案结论 |
| 写“只写可见内容”“不得补充价格和销量” | 这类指令不用写；直接写事实、不写不可见信息即可 |
| 把任务表、交付要求、客户名称写进去 | 目录描述只服务画面理解，不服务项目流程 |
| 在子目录里重复兄弟目录的内容 | 会造成越界注入和互相矛盾 |
| 把日期写进每个子目录 | 日期已在目录名里，除非日期对应不同产品或场景 |
| 写“这条素材 3.2 秒，适合开头” | 时长和用法由索引与剪辑判断，不由描述指定 |
| 在目录描述里写“画面要安详宁静” | 目录描述只写素材里有什么，不负责设定成片风格 |

**文字风格**

| 错误写法 | 问题 | 正确做法 |
|---|---|---|
| 用文字描述控制文字风格，比如“字体活泼、金色描边、标题醒目” | 文字风格不能靠提示词精确控制，描述也无法稳定还原 | 在剪映里做好样式草稿并导入，之后从资源目录选择 `dialogue_subtitle_style`（语音字幕）或 `global_subtitle_style_*`（固定文字） |
| 只写“要安详宁静的风格” | 抽象风格词没有对应的具体参数，系统无法直接执行 | Agent 拆成可执行项：语速与停顿、字幕样式、音乐、调色、特效强度、分段节奏、素材选择；每项都落到具体字段或资源预设 |

抽象风格要落到具体设定。例如“安详宁静”可以拆成：语速 0.9–1.0、选特定音色、停顿 300–500ms、字幕选简洁留白的样式、音乐从资源目录选安静的 BGM、分段节奏较慢、少花字少转场、素材偏空镜和自然光。Agent 转换前先检查资源目录里有没有对应样式和音乐。

### 3.3 用 CLI 一次写完

用 `material.manage --library primary` 一次提交 `operations` 数组：`create_directory` 只用于新建空目录或补充层级，`set_directory_description` 按 `path` 设置描述，根目录的 `path` 用 `.`。导入后目录通常已经存在，这时只提交描述操作。不要写本机绝对路径，也不要在描述里放兄弟目录的信息。

## 4. 举例不同需求怎么做

下表里的“错误”是常见错法，不要照做；同一需求按“正确”列使用对应字段。

### 4.1 旁白：单品

一条文案讲一个产品，画面从主素材库按卖点选择。重点是把文案里的动作、部件和卖点对应到具体画面。

| 想要 | 正确 | 错误 |
|---|---|---|
| 人声压住音乐 | `voice_track_volume` 2.0；`background_music_volume` 20–30 | 在 `material_matching_requirements` 写“人声要压过音乐” |
| 防重复要求严格 | `max_usage_count` 2–5；`top_usage_exclude_percent` 20–50；同时打开 `enable_random_scale`、`enable_random_offset`、`enable_random_rotation`；可选在匹配要求里写“已用次数偏高的素材禁止选用” | 不调使用次数和去重比例 |
| 产品细节必须匹配 | 在 `material_matching_requirements` 写具体动作、部件和证据 | 在 `ai_effect_strategy_prompt` 写“产品细节要清楚” |
| 不喜欢花字 | `enable_ai_effect_application` 保持开启，在 `ai_effect_strategy_prompt` 里写“不要花字，只保留必要的转场和音效” | 直接关闭 `enable_ai_effect_application`，把音效和转场一起关掉；或在匹配要求里写“不要花字” |
| 仅第一个镜头加额外文字标题 | 打开 `enable_ai_effect_application`，在 `ai_effect_strategy_prompt` 里写“只在第一个镜头加一个标题花字，后续镜头不再加文字类效果”，标题文案也写在这里 | 在`material_matching_requirements`写“只在第一个镜头加一个标题花字，内容是xxx” |

画面匹配要写具体：

```text
文案提到使用感受时，优先使用真实使用动作；
提到配料时使用手指产品配料表画面或安全证书画面；
```

如有分段要求：

```text
按卖点拆段，把材质、尺寸、功能、价格利益点分开，便于匹配对应镜头。
```

### 4.2 旁白：多产品与品牌宣传

**多产品同库**

核心是不同产品不能串画面，同一条视频里的画面色调要连贯。

| 想要 | 正确 | 错误 |
|---|---|---|
| 按目录取舍素材 | 打开 `enable_folder_candidate_ratio_control` 并填写 `folder_candidate_keep_ratios`；未配置的目录会被排除，此时不需要在匹配要求中禁止这些目录 | 只打开开关不填比例，以为系统会按目录平均分配；只在`material_matching_requirements`中写使用素材范围和禁用素材 |
| 画面场景和色调连贯 | 匹配要求里写“相邻画面优先同背景或同色系” | 把 `smart_color_adjust_value` 拉到 100，靠自动调色硬统一不同背景。 |
| 固定免责声明 | 打开 `enable_global_subtitle`，配置文字和样式 | 写进 `subtitle_markup_user_prompt` 或语音字幕分段提示，以为会一直显示 |

目录比例只在确实要按目录取舍时打开：

```json
{
  "enable_folder_candidate_ratio_control": true,
  "folder_candidate_keep_ratios": "产品A:100,产品B:60,网络素材:0"
}
```

**品牌或宣传片**

素材以官方片、实拍、资料和图片混合为主，可信度比“好看”重要。

| 想要 | 正确 | 错误 |
|---|---|---|
| 真实视频优先 | 匹配要求写“视频优先，图片只在缺视频时补充” | 在`folder_candidate_keep_ratios`中只写了`图片:100`，没有包含视频目录 |
| 固定证据镜头 | 匹配要求里指定目录、顺序 | 只把文件名改成“证据1/2/3”，不写匹配要求，顺序不会自动成立 |
| 标题或品牌常驻 | 打开 `enable_global_subtitle`，用多行标题样式 | 在 `subtitle_markup_user_prompt` 写标题 |
| 数字、缩写、品牌名读对 | `tts_pronunciation_optimization_prompt` 写易读错的内容 | 写进 `subtitle_sensitive_replacement_prompt`，只改字幕文字，读音不变 |
| 按段落加花字和转场 | `ai_effect_strategy_prompt` 写清段落、画面和文案 | 写进 `visual_segmentation_prompt`，只影响画面切换，不会加花字和转场 |
| 画面本身精致无需自动提升色彩 | 把 `smart_color_adjust_value` 降低或直接关闭 | 关闭 `enable_ai_effect_application`，以为能停止调色 |

匹配要求示例：

```text
优先使用真实视频素材，图片只在确实缺少合适视频时少量补充；
XXXX段落只用XX目录里的素材，先试用XX画面，再接XX画面。
```

### 4.3 旁白：已有配音

不调用 TTS，直接把语音配音库里的音频和画面合成。

| 想要 | 正确 | 错误 |
|---|---|---|
| 引用已有音频 | `audio_source=upload`，`audio_file_relative_path` 填语音配音库显示路径，路径规则见 [剪辑指南](editing-guide.md) 4.2 | 保留 `audio_source=tts`，只填 `audio_file_relative_path`；或填本机绝对路径 |
| 音频本身节奏很好 | `voice_speed_ratio` 1.0；停顿也合适时把 `speech_pause_target_ms` 设为 0，不剪气口 | 去调 `tts_speed`，已有配音不走 TTS，改了也没用 |
| 常规音频节奏 | `voice_speed_ratio` 1.2；`speech_pause_target_ms` 200–350 | 只改 `tts_speed=1.2`，`voice_speed_ratio` 仍为 1.0，成片速度不变 |
| 不要花字、音效、转场、贴纸 | `enable_ai_effect_application=false` | 在 `subtitle_markup_user_prompt` 中要求不添加花字（只有effect中的文字叫花字，markup中的是标记重点文字） |
| 只是不要花字 | `enable_ai_effect_application=true`，在 `ai_effect_strategy_prompt` 里要求“不添加任何文字” | 关闭`enable_subtitle_markup_optimization`/在 `subtitle_markup_user_prompt` 中要求不添加花字 |

`script_text` 可空；有原文时填入，只用于校正字幕，不必和音频逐字一致。上传音频时长必须在 0–600 秒之间。

### 4.4 片段口播

出镜素材是分散的多段短片，按文案或指令挑片段拼接。

| 想要 | 正确 | 错误 |
|---|---|---|
| 有明确文案 | 填 `script`，系统按文案选段并生成字幕 | 把文案写进 `instruction` |
| 只有主题、时长和结尾要求 | 填 `instruction`，不生成配音；不建议使用这条路径，应先和用户确定具体文案，再填 `script | 只把一句主题当 `script` 提交，成片只有这几个字；或 `instruction` 不写时长和结尾 |
| 某一行只用一个场景 | 在该行 `public_overrides.material_matching_requirements` 里限定 | 写在统一 `public_config.material_matching_requirements`，结果所有行都被限制 |
| 叠加产品画面 | `use_primary_overlay=true`，并确保主库索引就绪 | 只打开 `use_primary_overlay=true`，主库没索引，提交会被前置条件挡住 |
| 不叠加画面 | `use_primary_overlay=false`，主库不必索引 | 为了不叠加去清空或删除主素材库 |

片段口播需要先估算再提交。

### 4.5 完整口播

源视频是一条完整口播，只剪气口、字幕和包装；需要时再叠加主库画面。

| 想要 | 正确 | 错误 |
|---|---|---|
| 保留人物开场 | 匹配要求写“第一个镜头有人物时不覆盖” | 直接关闭 `use_primary_overlay`，整条视频都不叠加 |
| 覆盖黑屏或空白段 | 匹配要求写“其余黑屏、空白段必须覆盖” | 在 `visual_segmentation_prompt` 写“覆盖黑屏”，它只控制分段，不会加画面 |
| 不叠加任何画面 | `use_primary_overlay=false`，主库不必索引 | 打开 `use_primary_overlay`，再把主库素材全部禁用，靠空候选实现不叠加 |
| 只校正字幕 | `script` 填容易识别错误的词和专有名词，`instruction` 必须为空 | 在 `instruction` 写“只校正字幕”，完整口播要求 `instruction` 为空 |

匹配要求示例：

```text
口播第一个镜头有人物画面，不覆盖；其余黑屏、空白或没有有效画面的
片段必须完整覆盖。文案切换到另一个产品时，先使用该产品的外观画面
建立识别，再匹配功能、细节或使用场景。
```

完整口播需要先估算再提交。

### 4.6 图片型口播

主素材库以图片和少量开场视频为主，图片用来匹配文案里的具体名词，开场视频保证第一个画面是动态的。

| 想要 | 正确 | 错误 |
|---|---|---|
| 图片只用于具体名词 | 匹配要求写清“哪些词可以配图片、哪些语境不配图片” | 在 `subtitle_segmentation_user_prompt` 里限制图片 |
| 开场必须是动态画面 | 把开场视频目录的比例设为 100 | 在 `visual_segmentation_prompt` 写“开头用视频”，它不负责挑素材类型 |
| 控制图片重复率 | 打开目录比例控制，给图片目录设置 50–70，未配置目录会被排除 | 只把 `candidate_keep_ratio_percent` 降到 20，图片和视频一起被砍 |
| 语音字幕每个名词独立成段 | 用 `subtitle_segmentation_user_prompt` 要求名词所在短句独立成段 | 写进 `visual_segmentation_prompt`，只改变画面切换 |
| 规避敏感词 | 用 `subtitle_sensitive_replacement_prompt` 写成片文字替换规则 | 写进 `tts_pronunciation_optimization_prompt`，改了读音（不应改），但却不改字幕文字 |
| 图片必添加动画 | 打开 `enable_ai_effect_application`，在 `ai_effect_strategy_prompt` 里要求“所有图片镜头必须添加入场动画” | 只打开 `enable_random_scale`，随机缩放不是入场动画 |

匹配要求示例：

```text
图片只用于具体的物品、款式或名称型内容；
正面描述、场景描述、情绪描述不配图片；
开场必须使用视频，保证第一个画面是动态的。
```

需要时设置：

```json
{
  "enable_folder_candidate_ratio_control": true,
  "folder_candidate_keep_ratios": "图片:60,开头视频:100"
}
```

提交方式按 4.4 或 4.5，取决于口播源是多段短片还是一条完整视频。

### 4.7 视频节奏

节奏由分段要求控制，画面匹配要求只决定选哪些素材，不决定切多快。

| 想要 | 正确 | 错误 |
|---|---|---|
| 整体更快 | 在 `visual_segmentation_prompt` 写“整体节奏较快” | 在 `material_matching_requirements` 写“节奏快一点” |
| 整体更慢 | 在 `visual_segmentation_prompt` 写“整体节奏较慢，镜头停留更久” | 在 `material_matching_requirements` 写“节奏慢一点” |
| 精确控制 | 在 `visual_segmentation_prompt` 写“开头 3 秒每 5–8 个字切一次；产品特写每个2秒左右” | 在 `material_matching_requirements` 写“产品特写停 2 秒、开头多切” |
| 局部变化 | 写“开头快、产品特写慢，其余按默认” | 在 `material_matching_requirements` 写“开头快、后面慢” |

“较快”“较慢”可以给方向；要稳定复现，可用秒数、字数或单镜头时长写清楚。

### 4.8 固定文字：在需要时加

有法规、平台、免责声明或品牌标题要求时，才打开 `enable_global_subtitle`。法规提示用左侧或角标样式，免责声明用底部小字，AI 或内容声明放在不遮挡主体的位置，品牌标题用第一行、第二行标题样式。样式从资源目录选择；固定文字不参与语音字幕的分段和文字替换。字段规则见 [剪辑指南](editing-guide.md) 4.9。

## 5. 边界需求的变通方案

剪搭子只做语音驱动的剪辑，下面这些需求可以用变通方式实现，先向用户说明代价。

### 5.1 不需要语音，但需要持续显示旁白字幕

保留旁白文案，正常生成 TTS 和字幕，将语音音量调为 0：

- `audio_source` 仍为 `tts`，`script_text` 正常填写。
- `voice_track_volume` 设为 `0`，语音字幕照常保留。
- 这只是把成片人声音量调为 0，不是去掉语音轨；后期仍可在剪映里调整。

### 5.2 不是整段视频都在说话，中间需要一些停顿

在停顿处正常配音。例如需要停约 3 秒时插入配音「一二三四，二二三四，三二三四。」，即可做到约 3 秒停顿并插入 3 个镜头。

- 剪辑完成后需要人工在剪映里把这段占位配音静音，并删除这 3 段字幕。
- 也可以在 `subtitle_markup_user_prompt` 中要求删除所有类似「一二三四」的占位文字，减少后期删字幕的工作；占位配音仍需人工静音。

### 5.3 部分镜头是人物出镜口播，部分需要 TTS 配音

自行完成 TTS 配音，并将音频文件与人物口播视频一同导入人物口播库，即可正常剪辑。

- 口播库只接受带可读音轨的视频和音频；TTS 音频按普通候选素材参与选段。
- 导入后要完成索引，片段口播才能使用这些候选。
