# 首次使用快速指引（只用于第一次剪辑）

本文只在用户**第一次使用剪搭子 Skill**、还没有用它跑通第一条剪映草稿时阅读。目的是用最少的问题、最快的速度帮用户剪出第一条视频并装进剪映看真实效果；看片之后即转入日常使用，后续不再阅读本文。

## 1. 怎么判断是不是第一次使用（无需每次强制查文件）

- **优先凭当前对话与记忆判断**：如果用户在对话中已经用过剪搭子、主动提到之前的项目或预设、或你记得已经帮他交付过草稿，直接按日常流程走，**不需要读取本文，也不需要先查本地标记**，避免拖慢响应。
- **推荐的本地标记（跨会话辅助）**：只有在不确定用户是否第一次使用时，才顺手看一下 `~/.mycutbuddy/first-use-completed.json`（无需报错，文件不存在即视为首次）。
- **何时结束首次模式**：当第一条剪映草稿成功下载并安装到用户电脑的剪映草稿目录（或纯云端环境下已向用户交付草稿包），并告知用户如何打开看效果与如何提反馈后，随手写入 `~/.mycutbuddy/first-use-completed.json`（例如 `{"completed_at":"2026-11-02T12:00:00Z"}`）。此后即视为非首次使用。

## 2. 首次使用的核心原则：少问、默认、先看片

第一次使用时，用户还没有见过剪搭子剪出来的成片是什么样，此时追问一堆风格、节奏、包装细节只会让用户无从下手。

- **不要盘问细节**：只问下面第 3 节的 3 个最基本问题，其余全部按默认处理。
- **自动起项目名**：根据用户说的视频类型或产品名称直接自动起一个清楚的项目名（例如「某产品推广」「口播试剪」），并把用户说的视频内容简短写进主素材库根目录描述，**不要让用户专门为项目起名**。
- **第一次建议只剪 1 条**：就算用户手头有多篇文案，第一次也建议先挑 1 条试剪看效果，满意后再批量跑。

## 3. 开场怎么引导用户（只问这 3 件事 + 说明默认策略）

用简短自然的几句话引导用户，把「要问的 3 件事」和「第一次建议用默认配置」一次说清：

1. **要剪什么类型的视频**：比如是什么产品的推广、知识口播还是探店，画面里是纯素材配音还是真人出镜。
2. **素材在哪里**：在电脑哪个文件夹（优先直接上传），还是在百度网盘分享链接里。
3. **文案或配音在哪里**：直接发一段文案（默认用 AI 配音），或者告知配音音频、口播原视频的位置。

同时用一句话向用户交代**可定制范围与首次默认策略**：

> 「剪搭子支持自定义画面切换节奏、素材选用规则、文字与字幕样式、背景音乐、花字特效和音效等；不过第一次建议直接用默认配置先剪一条出来，你打开剪映看实际效果后，再告诉我哪些地方和你的剪辑习惯不一样、或者明确你的剪辑标准，我们再针对性调整。」

用户只要给出了这三项信息，就立刻开工，不要再追问音色、语速、花字、字幕样式或保留比例。

## 4. 账号授权与 200 赠送积分规划

1. **检查授权与余额**：先用 `credits.status` 检查是否已授权及当前可用积分；未授权时运行 `auth.login --wait` 请用户在浏览器点一次批准。
2. **为新用户赠送的 200 积分做预算规划（至少留出 1/4 即 ≥50 积分给剪辑）**：
   - 新手机号注册默认赠送 200 积分。这 200 积分要同时覆盖「上传导入素材 + 建立索引（及必要的多镜头分割）+ 至少剪辑 1 条成片」。
   - 单条常规短视频剪辑大约消耗 15～40 积分，因此**导入和索引合计最好控制在 150 积分以内，至少留出 1/4（约 50 积分）给第一次剪辑**。
   - **上传前先帮用户看一眼本地素材规模**：
     - 如果只是几十个短视频/图片（几百 MB 到几个 GB），积分完全充裕，请用户一次性授权本次「上传、索引和首条剪辑」的积分消耗，然后连续做完，中间不要反复打断。
     - 如果用户第一次就拿来很大的素材库（例如好几十 GB、几百上千条素材，或者包含大量很长的未切分多镜头成片），**必须在上传前提醒用户**：「新注册赠送 200 积分，建议至少留出 1/4（约 50 积分）用于剪辑出片；当前这批素材量较大，全部导入和索引可能会把积分用光导致不够剪辑。第一次测试效果建议先挑本次文案用得到的几十条核心素材（或单个子目录）上传试剪，看效果满意后再补传全量素材。」

## 5. 极简执行路径（全程用默认配置）

拿到用户的 3 项基本信息和积分确认后，由你连续执行完以下步骤：

1. **自动建项目**：调用 `project.create` 自动起名，不问用户。
2. **检查并上传素材**：
   - 先替用户快速扫一眼本地文件是否符合要求（无压缩包、文件名无 `..`、目录不超过 6 级）。
   - 用 `material.upload` 直接把素材传到对应素材库（旁白/B-roll 进 `primary`，真人出镜进 `talking_head`，现成配音进 `voiceover`）。
3. **写一句根目录描述并建立索引**：
   - 主素材库：用 `material.manage` 把用户刚才说的「剪什么产品/内容」写成根目录（`.`）描述；再看 `material.directory --library primary`——若都是用户实拍的一镜到底素材，选 `single`（处理费为 0）提交 `material.index.submit`；若包含宣传片或多镜头成片，跟用户确认一句后选 `mixed` 或 `multi` 处理并索引。
   - 人物口播库：如果是片段口播，直接提交 `material.index.submit`；如果是单条完整口播视频且不叠加主库画面，连索引都不需要。
4. **直接套用系统默认风格提交剪辑**：
   - 读取 `editing.context` 和 `preset.style.list`，直接选用当前剪辑形式下的**系统默认风格**，保持默认音色、默认字幕样式、默认特效与音效开关，所有提示词留空。
   - 旁白直接 `editing.submit`；口播先 `editing.estimate` 再 `editing.submit`。
5. **下载并装进剪映**：
   - 用 `request.watch` / `task.watch` 紧盯进度；一旦 `downloads[]` 里出现 `state=available` 的草稿包，立即用 `delivery.download` 直接下载到本机，再依次运行 `delivery.inspect`、`delivery.extract`、`delivery.install` 安装到剪映默认草稿目录（安装前提醒用户先关闭剪映）。

## 6. 看片引导与切换为日常模式

草稿安装完成后：

1. **写入本地首次完成标记**：在 `~/.mycutbuddy/first-use-completed.json` 写入完成记录，标记首次引导已结束。
2. **引导用户看片并提差异**：
   - 告诉用户打开剪映专业版，在首页按**今天的日期**找到刚装好的草稿播放看效果。
   - 明确告诉用户下一步怎么配合：「你先打开剪映看一遍成片效果，哪里跟平时自己剪的不一样、或者有明确的剪辑标准，直接用大白话告诉我——比如『节奏再快一点』『开头 3 秒多切几个画面』『不要花字只要音效』『换个更沉稳的声音』『提到某卖点时固定配某类画面』，或者把你剪映里做好的字幕样式导进来。我们马上按你的标准调第二版，调顺了还可以直接存成你的专属风格预设，以后每次都按你的标准剪。」
